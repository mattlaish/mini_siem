Start with incoming logs, review alerts, then investigate the evidence. Settings changes require an administrator unless the page says otherwise.

Get started

  1. Open Settings → Receive device logs for syslog devices, or Cloud log connections for services such as Sophos Central.
  2. Open Live logs & alerts and confirm that events arrive from the expected host. The status at the top reports recent collection activity, not a guarantee of lossless delivery.
  3. If logs are missing, use Check log delivery with the device IP, then review System Health.
  4. Configure Detection Rules and, for outside-hours monitoring, add each host and its Approved Hours.

Review alerts

The Alerts page starts with open alerts. Filter by severity, rule, assignee or text. Open an alert to see its reason, related events and history. Analysts and administrators can acknowledge it, assign an owner, add a note or move it to an allowed next status. Viewers can read but cannot make these changes.

New items wait behind the new-alerts button while you are reading. Use j/k to move through the list, Enter to open an alert, a to acknowledge it and Esc to close details.

Find events

Use Message, Source, Host, Destination, severity and time filters on Live logs & alerts. Press / to focus search. Filters stay in the page address so you can bookmark or share the same view.

Enter !term to exclude a term. Separate terms with commas. IP fields also accept a network such as 192.168.1.0/24. Available word-search behavior depends on this installation; use an exact field filter when precision matters.

Expand an event to see its fields and original evidence. Add a field as a column, or use field=value, for example action=deny. Choose whether multiple field conditions must all match or any may match. Export uses your current filters.

While you read an expanded event, type a search or scroll the list, new arrivals wait behind the new-events button. Counts can continue updating.

Manage detection and approved hours

On Detection Rules, turn rules on or off, tune repeated-activity limits or add custom conditions. Every condition in a custom rule must match. Choose Windows activity or All log sources. Custom field names use field. followed by the source field, such as field.action.

Edits are not active until you choose Save changes. A sample test uses your unsaved settings without saving events or creating alerts. A single sample cannot test rules that require repeated activity.

On Approved Hours, add hosts, time zones, allowed days and maintenance exceptions. Without an approved window, outside-hours detection is not checked. A window ending at 18:00 does not approve activity at 18:00. Overnight windows start on the selected day.

The web-server rule remains Critical at any time. An outside-hours exception cannot suppress it. Scope exceptions narrowly to approved programs, accounts, times and tickets; original logs and other detection rules remain available.

Threat intelligence

Add known malicious IPs, domains, URLs or file hashes on Threat Intelligence. Incoming logs are checked against enabled indicators. A match creates an alert and can be reviewed by AI when automatic analysis is enabled.

Paste one indicator per line, or CSV value,type,threat. Lines starting with # and duplicate indicators are skipped. Use a feed name to manage an import as a group.

For automatic updates, add a trusted feed URL and choose how often to check it. mini-SIEM must be able to reach that provider. Review any failed check shown next to the feed.

Connect a protected feed

Choose the access method specified by your feed provider. API credentials are encrypted when saved and are not shown again. Keep the provider's exact header or parameter names:

  • API key header: for example X-OTX-API-Key, Auth-Key or x-apikey.
  • Authorization header: sends the key exactly as required by providers such as MISP.
  • URL parameter: adds the key under the provider's specified parameter.
  • Username and password: HTTP Basic authentication.

Services using OAuth2 client ID and secret belong under Cloud log connections instead.

Search across log sources

Different products name the same address differently. Fortigate may use src, while Sophos uses endpoint_ip. In Settings → Search across log sources, list the fields that should also count as Source, Host or Destination.

These choices apply immediately to search and investigations, including earlier logs. No historical update is needed. To find a source's exact field names, expand one of its events.

Choose searchable fields

mini-SIEM recognizes common JSON and key-value logs automatically. In Log field mapping, choose which source fields should appear as Host, Message, Severity and Time.

Advanced users can add extraction patterns under Searchable fields and display columns in Log Search. These use regular expressions with named fields. Test carefully and keep the original event for reference.

New logs use saved patterns automatically. After changing a pattern, choose Update fields in earlier logs to make the new fields searchable in older events. This does not replay detection or change original log text.

Investigate related activity

On Investigations, run a ready-made security check, save a report or start from an IP address. Choose the time period and how many connection steps to follow.

A connection A → B does not automatically include B. B is followed only if it later sends traffic during the same period. Each further step needs the same evidence. Results link to the events that establish those connections.

An alert may come from one serious event or from a pattern across many events. Scheduled report findings can also raise alerts. Reports require mini-SIEM to remain running.

Monitor this server

Use Settings → Monitor this host to prepare forwarding settings for the SIEM server's own sign-ins, account changes and Linux audit activity. Your administrator must apply the generated settings on that server.

Authentication logs cover sign-ins, SSH and sudo. Detailed Linux audit records need the additional auditd connection shown on that page. These logs then appear in Log Search under the server's host name.

For missing logs or an overdue service update, check System Health. Its checks do not restart services or repair the database. Download a support report from Settings when you need help; review it before sharing.
