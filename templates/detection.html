Detection rules

Built-in message patterns stay code-owned; tune thresholds and windows here. Custom rules use an AND of field conditions (equals, contains or glob), with no executable code or arbitrary regex. Scope Windows evaluates Security 4688, Sysmon 1 and PowerShell 4104 events; scope All events also covers syslog, firewall, API and JSON logs using message, source.ip, host.name and any extracted key as field.<name> (e.g. field.action). Repeated all-events matches from one host/source link into one alert while they continue. The web-server rule is Critical at every hour and by default alerts on any process a web server launches (attackers can run any binary), except legitimate children you list as excluded; it cannot be exempted.

Host profiles
Use the hostname the events report. A short name (HMSWEB1) also matches that host's FQDN events (HMSWEB1.corp.example.com) and vice versa; different domains and IP addresses only match exactly. Groups select schedules and exceptions; web_server role qualifies java.exe/httpd.exe parents. The host IANA timezone interprets timestamps lacking an offset. Telemetry silence is opt-in: choose a threshold suitable for the expected activity or send regular heartbeat/test events. UDP delivery is not guaranteed.

Approved execution windows
Weekdays: Monday=0 … Sunday=6. End time is exclusive. Overnight windows belong to the starting weekday. Dates add approved dates; excluded dates remove holidays. No configured window means Out-of-Hours evaluation is skipped and shown as unconfigured.

  
Rule-specific approved exceptions
Each exception requires a host/group, full executable and parent paths, command pattern, account, approved window, expiry and ticket. The authenticated administrator is recorded as approver when saved. Exceptions match Windows process fields, so they apply to Out-of-hours shell, the NXLog/high-severity built-ins and Windows-scope custom rules; never to Web Server Spawning Shell, threshold burst rules or all-events rules. Raw logs and other rules continue.
