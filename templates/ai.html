Turn this on once your local LLM machine is ready. It stays off until then — no connections are attempted.

This assistant runs against your local LLM — no log data leaves your network. Its output is assistive analysis to speed up triage, not an authoritative verdict. Always verify against the raw evidence before acting. The model only sees context the server gathers for each request; it cannot run its own queries.

▼ settings
Data leaves your network in external mode. Every triage/chat request sends log context — source IPs, hostnames, usernames, alert details — to the external provider. With auto-triage on, this happens automatically for every alert. Only use a provider your data-handling policy permits, and prefer local mode for sensitive environments.

Point this at your local model's OpenAI-compatible endpoint. Ollama: http://localhost:11434/v1 (run ollama pull qwen2.5:7b first). LM Studio: http://localhost:1234/v1.

Any OpenAI-compatible provider works. Examples — OpenAI: https://api.openai.com/v1 · model gpt-4o-mini. Groq: https://api.groq.com/openai/v1. OpenRouter: https://openrouter.ai/api/v1. Paste the provider's API token below.
