Receive device logs

Choose the ports your devices use to send logs. 514 is the standard syslog port. Separate additional ports with commas, for example 514,10514. All ports use the same detection and forwarding settings. Restart the log collection service after saving a port change.

Restart required
Listen ports saved as . Ask your administrator to restart the log collection service to apply these ports. The web console can stay open. For installations using the standard service:
sudo systemctl restart mini-siem-listener
Use the installed service to keep the existing database connection and credentials.

Check log delivery

Enter a device IP to check whether its logs are reaching mini-SIEM. The 4-second check compares network arrivals, collection activity and recently saved events. Log message contents are not captured.

Each step is checked separately. A network arrival does not prove the event was saved or is searchable. Not confirmed means there is not enough information to verify that step; it does not mean the step passed. The check uses the source IP and receiving ports only; custom network filters are not supported.

Monitor this host

    
Send the SIEM server's own logs into mini-SIEM, so it watches
      itself — logins, sudo, SSH, account changes, and the Linux audit trail. A SIEM that can't
      see its own host is blind to attacks against itself. Pick the sources below and paste the
      generated config on this server. Learn more


    

      

        
        

          
          
          
        

      

    


    
    

      
      
      
      
    


    
1 · rsyslog forwarding config

    
Save as /etc/rsyslog.d/60-minisiem.conf on this server, then
      sudo systemctl restart rsyslog.

    


    

      
2 · Bridge auditd → syslog

      
auditd doesn't go through rsyslog by default. Enable its syslog plugin so audit
        records reach the config above:

      
sudo apt-get install -y auditd audispd-plugins   # if not already installed
# enable the syslog plugin:
sudo sed -i 's/^active = no/active = yes/' /etc/audit/plugins.d/syslog.conf 2>/dev/null \
  || sudo sed -i 's/^active = no/active = yes/' /etc/audisp/plugins.d/syslog.conf
sudo systemctl restart auditd

      
Tip: to specifically watch a sensitive file or directory, add an audit rule, e.g.
        sudo auditctl -w /home/matt/siem123/mini_siem/siem.db -p wa -k siem_db.

    


    
Once running, this host's events appear in Log Search like any other source —
      searchable, correlated, and forwardable. They'll show the SIEM server's own hostname.

      How to send logs
      

        
JSON (one object, a list, or {"logs":[…]}):

        
curl -X POST https://YOUR-SIEM/api/ingest \
  -H "X-API-Key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"severity":"warning","host":"appliance1","app":"imaging","message":"disk 90% full","disk":"/data"}'

        
Recognized keys: message/msg, severity/level, hostname/host, app/app_name. Any other scalar key (like disk) becomes a searchable field.

        
Raw syslog lines (Content-Type: text/plain, one per line) also work.

Syslog forwarding

    

      Relay every received syslog message — the original raw text, exactly as it arrived —
      to one or more downstream receivers, in addition to storing it here. Changes take effect
      within about five seconds without restarting log collection. Optional filters let a destination receive only
      a subset (by minimum severity and/or a regex over the raw message).
    

    

      Loop protection: destinations pointing at this listener's own address and port are automatically
      skipped by the listener. Still, be careful not to create indirect loops
      (A forwards to B, B forwards back to A) — each hop would re-receive and re-forward the same messages forever.
